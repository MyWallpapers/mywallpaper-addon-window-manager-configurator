# Impact et revue de code mort au périmètre A08

Périmètre de changement : ce nouveau dépôt uniquement. Le core MyWallpaper, le ledger, le moteur partagé et les autres add-ons ont servi de références de lecture. Le mécanisme externe remplace le besoin d’injecter ce configurateur dans toutes les applications ; il n’ajoute aucune responsabilité métier au moteur.

Codebase Memory a été consulté avant les lectures de code inconnu, puis le dépôt A08 a été indexé après implémentation : 580 nœuds, 1 374 relations au snapshot de revue. Les recherches de références exactes complètent le graphe pour les callbacks Windows et les clés de configuration dynamiques. Les degrés nuls du graphe ne constituent pas une preuve de code mort.

| Chemin affecté | Appelants, registrations et contrats vérifiés |
| --- | --- |
| `src/main.cpp` | `wmain` est le point d’entrée du binaire `companion` dans CMake. Le mode `--guardian` est lancé explicitement par `StartGuardian` ; aucun export DLL ou entrée Windhawk n’est déclaré. |
| `Runtime::Run`, `ReadFrames`, `Proc`, `Frame` | Démarrage depuis `wmain`, reader unique, envoi par `PostMessage(kFrame)`, `self->Frame`, procédure enregistrée dans `WNDCLASS.lpfnWndProc`. Le graphe ne relie pas seul tous ces appels indirects. Le reader attend le traitement de chaque frame, ce qui évite une file non bornée. |
| `Settings`, `Mouse`, `Keyboard`, `Event`, `Tick` | Procédures réellement enregistrées dans `SetWindowsHookEx`, `SetWinEventHook` et `SetTimer`. Retrait à la désactivation/arrêt. Le callback bas niveau de souris évite la requête COM de bureau virtuel ; les événements externes peuvent effectuer la qualification complète. |
| `Place`, `Execute`, `Own`, `SaveRecovery` | Raccourcis, règles d’ouverture, choix de zone, commandes process-v2 et menu tray. Le graphe trouve sept appelants de `SaveRecovery`. L’identité de processus, le marqueur de fenêtre et le cookie protègent les états retenus. Les demandes de position attendent la réalisation de la précédente avant une nouvelle demande. |
| `Cleanup` | Le graphe trace `~Runtime`, `Run`, `Frame`, puis `wmain`. Les messages de session Windows le déclenchent aussi. Nettoyage idempotent ; reader annulé et joint, hooks retirés, icon supprimée, états temporaires restaurés et journal restant conservé. |
| `StartGuardian`, `Guardian`, `RecoverPending`, `RestoreOwned` | `Frame(init)` lance le gardien ; `wmain --guardian` attend l’identité exacte du parent ; activation suivante reprend les journaux d’un propriétaire mort. Ready précède les mutations transitoires. Les lectures de fichier sont fermées avant suppression et les remplacements atomiques tolèrent brièvement les verrous de partage. |
| `Overlay::Proc`, `Show`, `Select`, `SavePreview` | Procédure enregistrée, callback de choix vers `Runtime::Choose`, rendu depuis palette/drag. `SavePreview` est appelé par la commande de fixture et emploie le même renderer sans afficher l’overlay. `Show` place l’overlay topmost sans activation et évite de redessiner un état inchangé. |
| `Manifest`, `ParseConfig`, `Layout` | En-tête embarqué généré depuis le même auteur de manifeste et profils. Les clés des trois règles sont produites et consommées par boucles nommées. Tous les paramètres sont dans le contrat public MyWallpaper ; les sections sont comptées. |
| Bundle et tests | `mywallpaper.config.json`, manifeste et CMake relient le point d’entrée PE x64 et les chemins d’output. Fixture C++ et driver Node font partie des tests, sans export runtime ni ajout à la distribution. L’entrée de zone de travail est exercée par le driver ; le contrat de lease est explicitement une proposition non implémentée dans le host. |

Suppression vérifiée : la méthode privée `Overlay::Save`, introduite pendant l’implémentation, n’avait plus d’appelant après l’ajout de `SavePreview`. Sa déclaration et sa définition ont été supprimées ensemble ; aucune registration, export, commande ou contrat externe ne la référençait. Le `Bitmap::Save` de GDI+ est distinct et conservé. Le champ auxiliaire `Search.current` n’était jamais lu et a été retiré du helper interne de recherche de fixture. Aucun symbole partagé, hook existant ou tranche arbitraire de commits n’a été supprimé.

La revue a aussi corrigé un effet réel observé du retour au placement : le chemin normal évite un `SetWindowPlacement` qui pouvait cacher la fixture non activante. Les changements de profils réappliquent maintenant un ensemble complet des valeurs visuelles et de disposition, tout en conservant la préférence personnelle de réduction des mouvements et les règles d’applications.

Finalisation du 15 octobre 2026 : 23 scénarios Win32, CTest MSVC/GNU et 77 définitions acceptées par le SDK public. `Place` (appelants `Execute` et `Opened`) réutilise son unique état de placement pour attendre la réalisation d’une requête instantanée avant mémorisation ; aucune nouvelle file ni génération de modules. `Settings` annule le glissement au lieu de déclencher `EndDrag` avec l’ancienne configuration ; `EndDrag` reste enregistré pour les fins de gestes. `Execute` conserve ses preuves de restauration tant qu’une API refuse l’opération. `Overlay::Show` (palette et aperçu de déplacement) préserve les styles existants ; la création topmost et l’affichage sans activation rendent les réouvertures cliquables. La procédure Windows et le callback `Choose` restent actifs et testés.

Suppression circonscrite : les variables `engineRoot`, `MW_NATIVE_ENGINE_ROOT` et `MW_NATIVE_ENGINE_SOURCE_DIR` ne faisaient que localiser la dépendance JSON du build ; recherche de références dans CMake, script, documentation et configuration de publication, puis remplacement par `third_party/nlohmann`. Ce ne sont pas des API runtime ni des exports dynamiques. Les deux fichiers MIT gardent exactement les empreintes verrouillées. Aucun symbole, contrat, source ou test du core ou du moteur n’est modifié. Les limites sont dans `qualification.md`, sans interpréter une compilation comme qualification de tous les hosts Windows.

Le complément de publication ajoute uniquement des documents et quatre preuves JSON : aucun symbole, registration, export, point d’entrée généré ou contrat externe n’est modifié ou supprimé. Il conserve le tag `v0.1.0` sur le commit source testé et cite le ledger courant sans créer une autorité de décision parallèle. Les références du README et de la qualification locale pointent vers le rapport exact du binaire central.
